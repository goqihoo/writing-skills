# 02 — 完成公司 Product Documentation 体系

**What to build:** 让用户可以为一家公司规划、生成、审计或迁移完整的 Product Documentation Set：公司级管理产品组合与治理，单产品管理稳定职责，并通过一个 Common Writer 覆盖低频标准文档而不扩大公共技能数量。

**Blocked by:** 01 — 建立统一的 Company Documentation 契约

**Status:** ready-for-agent

- [ ] 公司 Product 稳定核心包含 Portfolio、Governance 与 Products，并由 Product README 提供责任和真实导航。
- [ ] 只有已接受的产品才在 Products 下获得产品目录；产品线作为 Portfolio 分类视图而不是默认物理父目录。
- [ ] 每个已接受产品默认包含 Definition、Capabilities、Planning 与 Measurement，并拥有产品级责任 README。
- [ ] Solutions 与 Experience 只有在独立责任、治理或导航需要得到证明时创建。
- [ ] Initiatives、Evidence、Releases 与 Decisions 只有在第一份真实事件文档产生时创建。
- [ ] Product Lifecycle 保持跨现有文档的治理视图，不形成第二套目录树。
- [ ] 建立公司 Product 结构不强制要求单产品 Product Lifecycle Assessment；进入具体产品治理时继续使用该评估。
- [ ] reason-product 能判断公司产品组合、产品线、产品及下级边界，并在争议、扩展或迁移需要追踪时形成 Product Assessment。
- [ ] structure-product-docs 支持 proposal、scaffold、audit 与 approved migration，并遵循三种目录物化规则。
- [ ] write-product-doc 覆盖 Product 导航、Portfolio、Products Registry、Operating Model、Governance 以及已确认的单产品内部文档类型。
- [ ] Product Solution、Product Release Plan 与 Product Review 的模板、工作流和完成条件被并入 write-product-doc。
- [ ] Product Strategy、Capability Map、Product Roadmap、PRD 与 Product Metric System 继续由各自高频公共技能拥有。
- [ ] 被合并的低频公共技能和未实现的 Product Requirements 占位技能被移除，不保留别名或兼容包装。
- [ ] Product Common Writer 遇到独立公共制品时返回完整显式调用并停止，不执行目标技能。
- [ ] 所有生成或审阅 Product 正文的调用显式包含 write-doc；需要图表时由用户额外显式包含 draw-diagrams。
- [ ] Product 契约测试覆盖公司级核心、单产品核心、条件扩展、事件集合、内部类型路由、保留技能和移除技能。
- [ ] Product 的公共说明、技能列表、客户端元数据和推荐调用在本票据完成后保持一致并通过验证。
