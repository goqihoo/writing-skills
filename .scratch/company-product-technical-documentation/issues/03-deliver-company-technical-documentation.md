# 03 — 完成公司 Technical Documentation 与架构体系

**What to build:** 让用户可以为一家公司规划、生成、审计或迁移 Technical Documentation Set，并清晰区分公司技术架构、通用架构知识、系统下游权威和项目交付文档；通过四个技术公共技能覆盖稳定核心、条件扩展和事件文档。

**Blocked by:** 01 — 建立统一的 Company Documentation 契约

**Status:** ready-for-agent

- [ ] 公司 Technical 稳定核心包含 Strategy、Architecture、Systems 与 Governance，并由 Technical README 提供责任和真实导航。
- [ ] Platforms、Engineering、Data、Security、Quality 与 Operations 只有在独立责任、治理或导航需要得到证明时创建。
- [ ] Architecture Decisions、Governance Exceptions 与 Operations Incidents 只有在相应父责任存在且第一份真实事件文档产生时创建。
- [ ] reason-technical 能判断公司技术范围、Technical Landscape、所有权、权威边界、稳定职责和 Type Extension。
- [ ] Technical Assessment 只在边界争议、类型扩展、审计或迁移需要长期追踪时持久化，不成为 Readiness 或默认脚手架文件。
- [ ] structure-technical-docs 支持 proposal、scaffold、audit 与 approved migration，并且不使用代码仓库或项目交付目录模型。
- [ ] write-technical-doc 覆盖 Technical 导航、Strategy、Roadmap、System Landscape、System Profile、Operating Model、Governance 与 Standard。
- [ ] write-technical-doc 覆盖 Platform Definition、Engineering Practice、Data Governance、Security Governance、Quality Model 与 Operations Model 等条件内部类型。
- [ ] write-technical-doc 覆盖 Architecture Decision、Governance Exception 与 Incident Record/Review 等事件内部类型。
- [ ] System Profile 只保留公司需要的目的、所有权、生命周期、关键关系、治理状态和权威链接，不复制代码、配置或详细系统设计。
- [ ] write-technical-architecture 独立拥有公司 Technical Architecture，并内部应用 Technical Reasoning 与 Architecture Reasoning Shared Methods。
- [ ] 通用 Architecture Knowledge 由 write-architecture-knowledge 独立拥有，不形成公司实施承诺。
- [ ] 旧的 Study Architecture 与 Delivery Architecture 名称被原子替换，项目型 Technical Design、Decision Record 和交付架构占位能力退出当前 Technical 范围。
- [ ] 所有被替换或删除的技术技能不保留别名、兼容包装或旧公开标识。
- [ ] draw-diagram 继续作为独立 Visual 技能；Technical 或 Architecture 工作流在用户请求或结果确实需要视觉时内部应用 Visual Production。
- [ ] Technical 制品技能内部应用 Prose Quality 并独立完成正文；write-doc 保留为单独请求的通用写作结果。
- [ ] Technical 与 Architecture 契约测试覆盖稳定核心、条件扩展、事件集合、Common Writer 路由、Machine Authority 和新旧技能名称。
- [ ] Technical、Knowledge 与 Visual 的公共说明、技能列表、客户端元数据和推荐调用在本票据完成后保持一致并通过验证。
