# Technical Internal Document Types

Select exactly one Internal Document Type. This table owns the template and completion profile for `$Write Tech Doc`.

| Internal Document Type | Template | Completion profile |
| --- | --- | --- |
| Technical navigation | technical-readme-template.md | Responsibility, ownership, boundaries, real links, and downstream authorities are visible. |
| Technical Strategy | technical-strategy-template.md | Direction, choices, constraints, outcomes, investment implications, and review triggers agree. |
| Technical Roadmap | technical-roadmap-template.md | Outcomes, sequencing, dependencies, decisions, and review triggers are explicit. |
| System Landscape | system-landscape-template.md | Systems, owners, lifecycle, critical relationships, and authoritative links are discoverable. |
| System Profile | system-profile-template.md | Purpose, owner, lifecycle, relationships, governance, and downstream authority are current. |
| Technical Operating Model | technical-operating-model-template.md | Roles, forums, flow, interfaces, escalation, and cadence support governance. |
| Technical Governance | technical-governance-template.md | Decision rights, policies, evidence, exceptions, and review are enforceable. |
| Technical Standard | technical-standard-template.md | Scope, normative rules, rationale, verification, exceptions, and evolution are clear. |
| Platform Definition | platform-definition-template.md | Platform purpose, consumers, services, boundaries, ownership, and lifecycle are defined. |
| Engineering Practice | engineering-practice-template.md | Expected behavior, applicability, evidence, exceptions, and improvement triggers are operational. |
| Data Governance | data-governance-template.md | Data ownership, classification, lifecycle, controls, quality, and authority links are explicit. |
| Security Governance | security-governance-template.md | Security authority, risk decisions, controls, evidence, exceptions, and review are explicit. |
| Quality Model | quality-model-template.md | Quality attributes, measures, thresholds, tradeoffs, ownership, and review are explicit. |
| Operations Model | operations-model-template.md | Service ownership, operating boundaries, signals, escalation, recovery, and learning are governed. |
| Architecture Decision | architecture-decision-template.md | Accepted choice, alternatives, rationale, costs, authority, validation, and supersession are traceable. |
| Governance Exception | governance-exception-template.md | Deviation, authority, scope, risk, controls, expiry, and remediation are traceable. |
| Incident Record/Review | incident-review-template.md | Impact, timeline, evidence, contributing conditions, response, learning, and actions are distinguished. |

Company Technical Architecture is independently owned. Return `$Write Tech Arch $Reason Tech Docs $Reason Arch` and stop before drafting it. Selecting an Internal Document Type is routing within this skill, not another skill invocation.
