# Architecture Knowledge method

Select the smallest set of views that answers the reader's reusable question:

- **Domain:** meaning, invariants, boundaries, and state authority.
- **Application:** responsibilities, orchestration, contracts, and dependencies.
- **Governance:** decision authority, policy, controls, assurance, and exceptions.
- **Runtime:** execution, state transitions, failure, recovery, observability, and scaling.

For every proposed pattern or option, state:

- applicability and constraints;
- responsibilities and authority;
- benefits, costs, and tradeoffs;
- failure and recovery behavior;
- evidence and validation approach;
- transition and review triggers.

Keep company choices as examples or links. A company Technical Architecture, System Architecture, Project Documentation, or Machine Authority never becomes general Knowledge merely because it illustrates a pattern.
