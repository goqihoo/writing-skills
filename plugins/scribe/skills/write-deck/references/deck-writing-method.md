# Deck writing method

Use this method to turn supported material into one audience-facing presentation manuscript. A deck is a guided sequence, not a document divided into slide-sized pieces and not a topic inventory.

## Communication job

Define the communication job before choosing a narrative path:

> By the end, this audience should reach this outcome because they understand or accept this central point.

Record the audience's starting context, the setting, the available time or page budget, the requested action, and the evidence or boundaries that must remain visible. Resolve only missing information that would materially change the result; otherwise make a visible, conservative assumption.

## Delivery mode

Select the delivery mode from the actual use:

- **Live:** concise screen copy; speaker support carries explanation, examples, and qualifications.
- **Live with leave-behind:** screen copy retains the essential evidence and conclusion; speaker support adds depth without owning facts the audience must later recover.
- **Read-alone:** each page carries enough context to work without a presenter; transitions may be structural rather than spoken.

Delivery mode changes density and where explanations live. It does not change source authority or justify omitting a necessary premise.

## Narrative path

Derive one cumulative narrative path from the communication job. These common movements are examples, not registered deck types or fixed outlines:

- learning: starting point → model → method → application → check;
- explanation: question → objects → mechanism → failure → boundary;
- product introduction: audience problem → value → behavior → fit → next step;
- business case: opportunity → insight → proposal → evidence → result → request;
- decision: decision → criteria → options → recommendation → cost → review trigger;
- plan: goal → current state → gap → approach → execution → risk → decision;
- review: expected state → observed result → variance → cause → response.

Compose or adapt these movements when the subject requires it. Keep one primary path so business, product, technical, learning, and planning material contribute to the same audience outcome rather than becoming adjacent mini-decks.

## Deck plan

Lock these responsibilities before drafting slide bodies:

1. The opening makes the situation, question, stakes, or purpose worth attention.
2. Each section completes one meaningful movement and leaves an output the next section uses.
3. Each slide has one slide job and one primary point, supported by only the evidence or example it needs.
4. The ending resolves the opening with a synthesis, application, decision, request, or productive question.

Build the title sequence first. A title is the audience's entry point, not a production instruction. Read only the titles and confirm that the narrative path remains intelligible, the abstraction level does not jump without support, and repeated pages do not answer the same question.

Run the adjacent-slide test for every pair: because the previous slide established this result, the audience now needs this slide. Reorder, bridge, merge, or remove a page when that relationship cannot be stated.

## Slide contract

Use only the fields that help produce or verify the slide:

- **Slide job:** the change in audience understanding, belief, decision, or ability this page owns.
- **Screen copy:** audience-facing content that makes the primary point and necessary evidence visible.
- **Speaker support:** reasons, examples, boundaries, likely misunderstandings, and delivery guidance needed in the selected delivery mode.
- **Transition:** the causal, conditional, contrasting, or sequential reason the next page appears.
- **Visual direction:** the relationship or evidence a visual must make easier to see, when a visual is warranted.
- **Source notes:** links or citations for consequential claims and external assets.

Do not print production fields as audience copy. Important evidence and examples must appear in screen copy when the audience needs them to understand the page or use the deck later.

## Natural expression

The shared Prose Quality Method owns the natural-language contract. Apply it after the deck plan is stable, separately to each writing surface:

- titles should sound like a point or question a presenter would naturally say to this audience;
- screen copy should be concise and audience-facing without collapsing into slogan fragments;
- speaker support should use speakable sentences without filler, fake spontaneity, or narration of the template;
- each transition should state a real relationship instead of announcing that another topic comes next.

Natural expression changes with audience, relationship, and delivery mode. It does not make business, product, technical, and learning presentations use the same voice, and it never overrides exact code, formulas, labels, quotations, facts, or qualifications.

## Visuals and evidence

Choose a visual only when it materially reduces reconstruction work. State the reader question and supported relationships before selecting a diagram, chart, image, table, or other visual grammar. Follow a binding local visual guide when present. Keep brand rules and project-specific visual tokens in their owning project rather than copying them into the general deck method.

Treat the presentation manuscript as a derived expression. Link the source that owns each company fact, product commitment, technical truth, project state, measurement, or decision. Separate observations, interpretations, proposals, assumptions, and open questions.

## Length and variants

Use duration and page constraints to set scope and pacing. When a shorter version is requested, derive it from the complete narrative instead of relying on faster delivery. Preserve the opening, primary path, decisive evidence, necessary transitions, and ending; compress examples, secondary comparisons, and deep implementation detail first.

## Completion checks

- The communication job, delivery mode, and source boundary are explicit.
- The narrative path is cumulative and survives the title-sequence test.
- Every adjacent pair has an explainable relationship.
- Every slide has one distinct job and enough visible support for its delivery mode.
- Titles, screen copy, speaker support, and transitions satisfy the shared natural-language contract.
- Consequential claims and external assets remain traceable.
- The ending produces the intended audience outcome.
